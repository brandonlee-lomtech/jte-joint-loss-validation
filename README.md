# Lightweight prototype: exact joint-loss reference solver (ADB Quantum Joint-Loss Challenge)

**ADB Quantum Innovation Challenge: Joint-Loss Modelling for Disaster Risk Financing, Phase 1 lightweight prototype.**
Applicant: LOMTECH GLOBAL Co., Ltd. (Republic of Korea).

## Purpose

This repository is the *minimum viable* validation of our Technical Proposal. It shows, with code a judge can run in about a minute on one CPU core, that the representation at the heart of our proposal works on the official benchmark:

* each country is one tensor site (local state = earthquake payout level 0-4 x precipitation trigger 0/1, d = 10);
* cross-border dependence lives entirely in the bond between sites (independent countries: bond dimension 1; the official dependent scenarios: 9 for the annual law, 10 for the 3-year term law);
* every official target is obtained by **exact contraction**, with no sampling error, including the rare joint-tail target "both bonds exhausted" that all four official samplers miss in every scenario.

It contains a small, readable **reference solver** for the official **two-country** ADB model and the World Bank ELT track. It is **not** our full engine; see [What is withheld and why](#what-is-withheld-and-why).

> **Labels.** Everything here is a classical CPU execution (`execution = classical_cpu`). No GPU, cloud service, quantum simulator or quantum hardware was used. We make **no speed-up claim**: on the official two-country model, run time is at parity with the official exact solver.

## Quick start (Linux or macOS, Python 3.12; 3.10+ should work)

```sh
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.lock.txt
pip install --no-deps -e ./vendor/qjlb-benchmark      # official benchmark package (provides `qjlb`)
./run_all.sh                                          # tests + all numbers and figures below (~15 s)
PRACTICE=1 ./run_all.sh                               # + official `qjlb holdout` / `qjlb evaluate` practice suite (~5-10 min)
```

Expected final lines of `./run_all.sh`:

```text
13 passed
25/25 official ADB targets reproduced (max relative error 2.0e-12); qjlb validate: all passed
10 World Bank targets, max relative error vs official exact 0.0e+00
This solver passes 25/25 targets.
Official samplers failing (of 25): MC 17, Sobol 16, Strat. 9, IS 10
P(both exhausted): samplers passing in 0/5 scenarios
```

Expected final line of the practice suite: `team solver: 6/6 practice cases pass`.

Official evaluation command for this team solver (both tracks):

```sh
qjlb evaluate <suite> --execution classical_cpu --trusted-code -- python "$PWD/team_solver.py"
```

## What is in this repository

| Path | What it is |
|---|---|
| `src/jlref/two_site.py` | Exact two-site MPS: SVD split of the official 10 x 10 annual law, site-wise capped convolution over the term with exact two-site recompression, transfer pass for the five official targets. |
| `src/jlref/elt.py` | World Bank ELT track: exact vectorised pass over catalogue rows (**not** a tensor network; labelled `jlref_elt_exact_vectorised`). |
| `src/jlref/solver.py` | Official-interface `solve(model, samples, seed)`, dispatching to the two tracks. |
| `team_solver.py` | Entry point for `qjlb evaluate`. |
| `scripts/reproduce_adb.py` | All 25 official ADB targets; official-format files in `results/adb/`, each checked with `qjlb validate --rtol 1e-9`. |
| `scripts/reproduce_wb.py` | World Bank public scenarios vs the official exact solver. |
| `scripts/compare_baselines.py` | Two-country comparison against the official MC, Sobol QMC, stratified and importance samplers (`qjlb run`, 10 x 8,192, seed 0). |
| `scripts/practice_suite.sh` | Official `qjlb holdout` + `qjlb evaluate` on a 6-case practice suite (seed 20261125). |
| `scripts/make_figures.py` | `figures/fig1_adb_errors.png`. |
| `tests/` | 13 tests for the included code. |
| `results/` | Outputs of the scripts above (regenerated by `run_all.sh`). |
| `REPORTED_RESULTS.md` | Numbers from the Technical Proposal produced by the full engine, **not reproducible from this repository**, copied verbatim and clearly labelled. |
| `vendor/qjlb-benchmark/` | Official benchmark, unmodified (Apache-2.0; World Bank data CC BY 4.0). See `NOTICE`. |

## What is withheld and why

The Challenge asks for a *lightweight* prototype that validates the proposal. We publish the minimum needed to verify our claims on the official benchmark, and withhold the parts of our engine that are our core know-how:

| Withheld | Role in the full engine | Covered by public evidence here? |
|---|---|---|
| Automatic bond-dimension (chi) selection | chooses the dependence rank so that the decision targets converge | No (the public solver uses an exact rank, which is only affordable for n = 2) |
| Non-chain and long-range dependence handling | regional shocks, long-range and all-pairs dependence between many countries | No |
| Large-n scaling (n-country construction and contraction) | portfolios of tens to hundreds of countries | No; results only, in `REPORTED_RESULTS.md` |
| Decision layer | premium, VaR/ES capital, diversification benefit, joint trigger and joint exhaustion | No; results only |
| Dependence stress tests | independent / Gaussian / Student-t / shared-event assumptions | No; results only |
| Quantum-model experiments (QCBM, QAE circuit construction) | negative result and resource estimation | No; QAE resource numbers only, in `REPORTED_RESULTS.md` |

The public two-site recompression contracts back to a dense 10 x 10 matrix each year. That is exact and fast for two countries but costs O(10^n) and is not how the full engine scales.

**Access for the evaluation panel.** The full engine and the scripts that produce every number in `REPORTED_RESULTS.md` are available to the ADB evaluation panel on request, under confidentiality, in Phase 2.

## Environment

* Python 3.12.16 (CPython), Linux x86_64 (kernel 6.12, glibc 2.41).
* Exact package pins: `requirements.lock.txt` (numpy 2.5.5, scipy 1.18.1, matplotlib 3.11.2, pytest 9.2.0). Direct dependencies: `requirements.txt`.
* Official benchmark: `vendor/qjlb-benchmark`, joint-loss-baseline v0.5.0, unmodified (byte-identical to the official public ZIP; checks against its `SHA256SUMS`).
* Hardware used for the numbers in `results/`: virtual machine (KVM), Intel Xeon Processor (family 6, model 207), 8 vCPUs (1 thread per core), 15 GiB RAM. **No GPU.**
* Simulators and quantum hardware: **none** used in this repository.
* Timings depend on the machine; accuracy results do not (deterministic).
